# Demo Console (Web UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

- **Status:** approved
- **Date:** 2026-10-27

**Goal:** A local web "demo console" (`python src/webui.py`) showing the customer chat, a secure payment card and a live redacted "under the hood" panel for the unchanged rental-extension agent, with one-click demo scenarios.

**Architecture:** `src/webui.py` holds four units: `WebPaymentCollector` (a `PaymentCollector` that blocks the tool's thread until the browser answers), `DemoSession` (one agent conversation run turn by turn in worker threads), `DemoApp` (routes JSON requests to the current session; `dispatch()` is testable without sockets) and a thin `ThreadingHTTPServer` handler. `src/static/index.html` is one plain page that polls `/api/state`. The per-message body of `chat_loop` moves into `agent.respond`, shared by the CLI and the web worker.

**Tech Stack:** Python 3.10+ standard library (`http.server`, `threading`, `json`), openai-agents 0.24 (unchanged), plain HTML/CSS/JS, pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-10-27-demo-ui-design.md` (its gate record has the same file name under docs/superpowers/gates/). Read the spec's Design section before Tasks 3–6.

## Global Constraints

- No change to agent behaviour: `INSTRUCTIONS`, the tools, guardrails, thresholds, payment rules and `RoadwayClient` stay as they are. Existing `tests/test_agent.py` tests pass unchanged.
- No new Python, npm or Node dependencies; no CDN, no build step. `src/static/index.html` is one file (HTML, CSS, JS).
- Server binds `127.0.0.1`, port `8765` by default, `WEBUI_PORT` overrides. One demo session per process; no auth.
- Roadway blue `#1f5fbf` appears in `src/static/index.html` only in the header accent rule. Customer bubbles dark slate `#2f3e4e` with white text; agent bubbles light gray. Blue is never used for chat bubbles.
- Card details (CVV, billing ZIP) go only from the request handler to the waiting `collect` call; never into the trace, chat, log file, model history or any `/api/state` response.
- Payment collector timeout: 5 minutes (`300.0` s). Cancel, invalid input, timeout or reset return `None`.
- Browser polls `/api/state` about every 500 ms while a turn runs or a payment is pending, every 3 s otherwise. Autoplay pauses about 1.5 s before each send.
- Card validation patterns: `CVV_RE = ^\d{3,4}$`, `ZIP_RE = ^\d{5}$` (from `src/payment.py`), in the browser and again on the server.
- Unit tests are network-free (loopback `127.0.0.1` sockets are allowed; no external hosts). `python -m pytest -q` and `ruff check src tests evals && ruff format --check src tests evals` must pass. Keep `ruff.toml` as is.
- This repo is public: no private repo names or machine usernames in tracked files.

## Review Focus

1. **Reset or a scenario click while a turn runs (with or without a payment card waiting):** the new session starts empty and idle; the old turn's reply never appears in it; a waiting `collect` returns `None`. Test: `test_reset_during_turn_isolates_old_worker` (Task 3).
2. **A second payment answer (double-click Authorize, or a POST with no card waiting):** HTTP 409, the first answer stands. Tests: `test_answer_without_pending_returns_false` (Task 2), `test_payment_without_pending_is_409` (Task 3).
3. **The model call raises mid-turn:** the chat gets `TURN_ERROR_REPLY` (or the charge outcome), `busy` clears and the next message is accepted. Test: `test_turn_error_reply_and_busy_cleared` (Task 3).
4. **The reservation read fails when a scenario is chosen (mock down):** HTTP 502 with a readable `error`, the session is still fresh, no exception escapes. Test: `test_choose_scenario_reservation_failure_is_502` (Task 4).
5. **Malformed request bodies (not JSON, not an object, missing `text`, unknown path):** HTTP 400 / 404 JSON, never a 500 or a dropped connection. Test: `test_bad_requests` (Task 5).

### Task 2: `WebPaymentCollector`

**Files:**
- Create: `src/webui.py` (module docstring + this class only for now)
- Test: `tests/test_webui.py`

**Depends on:** none

**Interfaces:**
- Produces, in `src/webui.py`:
  - `PAYMENT_TIMEOUT_S = 300.0`
  - `class WebPaymentCollector` implementing the `PaymentCollector` protocol of `src/payment.py`:
    - `__init__(self, timeout: float = PAYMENT_TIMEOUT_S, on_request: Callable[[dict], None] | None = None)`
    - `collect(self, amount, currency, card_type, last_four, description) -> PaymentDetails | None` — builds the public request item `{"role": "payment", "amount": float, "currency": str, "card_type": str | None, "last_four": str | None, "description": str, "status": "pending"}`, stores it as pending, calls `on_request(item)`, then waits on a `threading.Event` up to `timeout`. On return it clears the pending request and sets `item["status"]` to `"submitted"` (details returned), `"cancelled"` (cancel, invalid input or reset) or `"expired"` (timeout). The item never holds card details.
    - `pending(self) -> dict | None` — a copy of the pending item without `"role"`/`"status"` keys (`amount, currency, card_type, last_four, description`), or `None`.
    - `answer(self, cvv: str | None = None, billing_zip: str | None = None, cancel: bool = False) -> bool` — `False` when nothing is pending or it was already answered; otherwise resolves the wait: `PaymentDetails(cvv, billing_zip)` when both match `CVV_RE`/`ZIP_RE` (after `.strip()`) and `cancel` is false, else `None`; returns `True`.
    - `cancel_pending(self) -> None` — resolves a pending wait with `None` (used by reset); no-op otherwise.
  - Guard the pending slot and the "answered once" flag with one `threading.Lock`.

### Task 3: `DemoSession`, `DemoApp` and the `/api/state` shape

**Files:**
- Modify: `src/webui.py`
- Test: `tests/test_webui.py`

**Depends on:** Task 1, Task 2

**Interfaces:**
- Consumes: `agent.respond` (Task 1); `WebPaymentCollector` (Task 2); `ConversationState` fields `session_id, verification, reservation_id, email, quotes, handoffs, trace`; `Quote.charges["total_charged"/"currency"], status, created_at`; `Settings.quote_ttl_minutes`; `telemetry.mask_email`.
- Produces, in `src/webui.py`:
  - `class DemoSession`: `__init__(self, agent, deps: ToolDeps, collector: WebPaymentCollector, runner=Runner)`. Sets `collector`'s `on_request` to append the item to `self.chat` (so the card is a chat item, appended at the moment it is requested, and stays in the chat after it is answered with its final `status`). Attributes: `agent`, `deps`, `collector`, `runner` (the constructor arguments), `thread: threading.Thread | None` (the latest turn's worker, set in `start_turn`), `chat: list[dict]` (`{"role": "user"|"agent", "text": str}` or payment items), `history: list`, `busy: bool`, `closed: bool`.
    - `start_turn(self, text: str) -> bool` — `False` if `busy`; else appends the user chat item, sets `busy`, starts a daemon `threading.Thread` that calls `respond(agent, deps, history, text, runner=runner)` and then, under the session lock and only if `not self.closed`, stores the new history, appends `{"role": "agent", "text": reply}` and clears `busy`. A `closed` session's worker discards its result.
    - `state(self, since: int = 0) -> dict` — the `/api/state` body (below).
    - `close(self) -> None` — sets `closed`, calls `collector.cancel_pending()`.
  - `class DemoApp`: `__init__(self, make_session: Callable[[], DemoSession])`; `session` (current); `reset(self) -> DemoSession` (closes the old session, makes a new one); `dispatch(self, method: str, path: str, body: dict | None) -> tuple[int, dict]` handling:
    - `GET /api/state?since=N` → 200 `state(N)` (`N` defaults to 0; a non-integer → 400).
    - `POST /api/message {text}` → 400 `{"error": ...}` when `text` is missing, not a string or blank after `.strip()`; 409 `{"error": "busy"}` when a turn runs; else 202 `{"ok": true}`. Exit words are not special in the web console.
    - `POST /api/payment {cvv, billing_zip}` or `{cancel: true}` → 200 `{"ok": true}` when `collector.answer(...)` returns `True`, else 409 `{"error": "no payment pending"}`.
    - `POST /api/reset` → 200 `{"session_id": new_id}`.
    - Anything else → 404 `{"error": "not found"}`. (Scenario routes are added in Task 4.)
- `/api/state` JSON shape (Task 6 renders it):

```json
{
  "session_id": "1a2b3c4d",
  "busy": false,
  "chat": [{"role": "user", "text": "..."}, {"role": "agent", "text": "..."},
           {"role": "payment", "amount": 142.3, "currency": "USD", "card_type": "Visa",
            "last_four": "4421", "description": "...", "status": "pending|submitted|cancelled|expired"}],
  "payment": {"amount": 142.3, "currency": "USD", "card_type": "Visa", "last_four": "4421", "description": "..."},
  "status": {
    "identity": {"verification": "unverified|verified|email_unconfirmed", "reservation_id": "RWR-... or null", "email": "d***@example.com or null"},
    "quote": {"total": 142.3, "currency": "USD", "status": "presented", "expires_at": "2027-06-14T17:15:00+00:00"},
    "handoffs": [{"reason": "high_value", "reference": "HO-..."}]
  },
  "trace": [{"ts": "...", "event": "tool_call", "...": "..."}],
  "trace_next": 42
}
```

`payment` is `collector.pending()` (or `null`); `quote` is `null` when there is none, else from `state.latest_quote()` with `expires_at = (created_at + timedelta(minutes=deps.settings.quote_ttl_minutes)).isoformat()`; `trace` is `state.trace[since:]` (already redacted), `trace_next = len(state.trace)`. Build `chat` from shallow copies under the session lock.

Test injection point: `DemoApp(make_session)` takes the session factory and `DemoSession(..., runner=...)` takes the runner, so tests pass `fakes.make_deps(...)` deps and a fake runner; nothing in the web layer builds a real client, KB embedder or model unless `build_session` (Task 5) is used.
